# 通用文本文件拆解指导：让文本内容对 LLM 易读

> 版本 v1.2 ｜ 定位：面向需要把"文本文件"预处理成 LLM 友好形式（问答、摘要、检索、补全、生成等下游任务）的工程与产品文档。

---

## 0. 文档说明

### 0.1 这份文档解决什么问题

任何把文本喂给大语言模型（LLM）的场景，几乎都绕不开同一件事：**原始文本往往太长、太杂、结构对模型不友好，需要先"拆"再"取"**。本指南回答五个问题：

1. 按什么**逻辑**拆（而非机械切块）；
2. 这套逻辑能否**跨文本类型通用**（代码、对话转写、法律、文本表格、叙事、邮件……）；
3. 拆完如何**保证质量**、如何**评估**；
4. 如何**选型落地**、上线后**如何维护**；
5. 除了拆解，还有哪些**精简、节省上下文**的策略。

### 0.2 范围声明（只覆盖文本文件）

本指南**只覆盖文本文件**——即一切以文本为载体的内容：

- 纯文本（.txt / .md / 代码）；
- 文档导出的文本（.docx / 带文本层的 .pdf）；
- 语音转写文本、对话记录；
- 文本形式的表格（Markdown / CSV / TSV）。

**明确排除**：图像、音视频、扫描件/图片型 PDF 等需要 OCR、语音识别、视觉理解等"模态转换"的二进制媒体。若内容含这些，应**先完成转换得到文本**，再按本指南处理；转换本身不在本文档范围内。

### 0.3 读者与前置

- **读者**：设计检索增强（RAG）、知识库、文档问答、代码助手、会议助手等系统的工程师与产品负责人。
- **前置**：对"向量检索 / 上下文窗口 / 嵌入"有基本概念即可；技术细节处给出可替换的简化方案。

### 0.4 术语约定

| 术语 | 含义 |
|---|---|
| **块（Chunk）** | 拆解后送入模型的最小交付单元 |
| **原子单元（Unit）** | 文本语义上不可再分的完整单元（如一个函数、一个话轮、一个命题） |
| **自包含（Self-contained）** | 脱离全文仍可被独立理解 |
| **关系（Relation）** | 块与块之间的语义连接（引用、调用、回复、因果……） |
| **元数据（Metadata）** | 附着在块上、但不参与嵌入/语义匹配的结构化标签 |

## 1. 核心思想：切块不是目的

### 1.1 先认清 LLM 的四个客观限制

拆解动作本质上是在对抗以下限制，拆法是否合理，取决于它是否缓解了这些限制：

| 限制 | 含义 | 拆解对策 |
|---|---|---|
| **上下文窗口有限** | 长文塞不进，或塞进去挤掉其他信息 | 切成可独立取用的片段 |
| **注意力稀释（Lost in the Middle）** | 长文本中间的信息最容易被忽略 | 片段要短、要点靠前 |
| **检索粒度错配** | 固定长度切块会导致问题与答案跨块 | 按语义单元切，而非固定长度 |
| **结构信息丢失** | 变纯文本后，标题/表格/引用关系没了 | 显式保留结构元数据 |

### 1.2 由此得到"易读"的判定标准

一条文本对 LLM "易读"，当且仅当满足：

1. **自包含**——单块脱离全文即可理解；
2. **语义完整**——不把完整意思拦腰斩断；
3. **粒度匹配**——块的大小同时对齐下游任务需求与检索/嵌入能力；
4. **上下文可追溯**——带着足够的来源与关系标签。

### 1.3 通解的本质：不变量 + 变量

跨文本类型的通解，是把"切块"这件事**抽象成两层**：

- **不变量（骨架）**：一套不随内容改变的流程——解析、建结构、定单元、切块、补上下文、保关系。任何文本都走这六步。
- **变量（旋钮）**：五个随内容改变的参数——结构容器、边界检测器、关系类型、上下文模板、粒度映射。

> 一句话：**切的是"意思"而不是"长度"，补的是"上下文"而不是只留"正文"；骨架不变，旋钮按类型替换。**

> 补充：拆解只解决"边界与取用"；"给 LLM 读"还关心"同样信息用多少 token 表达、何时用摘要、何时用原文"——那是**精简策略**，与拆解正交、可组合，见第 13 章。

## 2. 通用骨架：六步法

任何类型的文本，按以下顺序处理。每一步统一给出：**输入、动作、产出、失败兜底**（兜底是让流程在任何输入下都不中断的关键）。

```
[1] 还原解析 parse --> [2] 建结构树 structure --> [3] 定语义单元 unit
                                                        |
[6] 保关系+索引 index <-- [5] 补上下文 context <------ [4] 切块 chunk
```

### 步骤 1：还原解析（Parse）

- **输入**：纯文本 / 文档导出文本 / 代码 / 转写文本……
- **动作**：编码归一 -> 去页眉页脚/导航/模板噪声 -> 还原段落与换行。
- **产出**：一个语义上干净的线性文本 + 原始结构线索。
- **失败兜底**：乱码或异常段落，**原样保留并打上"低置信"标记**，交给下游降级处理，绝不静默丢弃。

### 步骤 2：建结构树（Structure）

- **输入**：上一步的中间表示。
- **动作**：识别标题层级 / 代码语法树 / 会话与话题 / 编章条款 / 表结构，建成树。
- **产出**：一棵结构树，树的分支就是切块的天然边界。
- **失败兜底**：识别不出结构时，退化为**扁平列表**（无层级），按空行/标点做段落边界，进入规则切模式（见第 6 章降级路径）。"切块永不跨层级"这一原则只在树存在时生效。

### 步骤 3：定语义单元（Unit）

- **输入**：结构树。
- **动作**：明确"不可再分的最小完整单元"是什么（每种类型不同，见第 4 章）。
- **产出**：单元清单。
- **判定标准**：**把单元单独拿出来，一个懂行的读者能否看懂它本身？** 能，才是合格单元；不能，说明单元定大了或定错了。
- **失败兜底**：单元判定不清时，默认以"段落"为单元，再靠步骤 5 的上下文补全来补救。

### 步骤 4：切块（Chunk）

- **输入**：单元清单。
- **动作**：沿结构边界把单元聚合/拆分成"恰好够用"的块。
- **方向**：**自底向上聚合**（多个小单元合成一块）优于自顶向下硬切。
- **产出**：块清单。长度是**结果不是切法**：先按语义边界切，长度自然落在合理区间。
- **失败兜底**：单块超长（如一个巨大表格或函数）时，按内部子结构（行/子句/子函数）再切，并标注"本块是父单元的片段 [i/n]"。

### 步骤 5：补上下文（Context）

- **输入**：块清单。
- **动作**：两类补全——(1) 前置上下文头（标题路径、说话人、作用域等"你在哪"）；(2) 指代消解/补全（把"该/它/上述/综上"替换或补充为明确对象）。
- **产出**：自包含的块。
- **失败兜底**：无法可靠消解的指代，宁可**保留原文 + 附上"本块依赖上文"标记**，也不做可能改错语义的硬替换。
- **注意**：补上下文会引入冗余，需与嵌入质量权衡（见第 8 章权衡 1）。

### 步骤 6：保关系 + 索引（Index）

- **输入**：自包含的块。
- **动作**：记录块之间的关系（调用、引用、回复、因果……），并分层入库。
- **产出**：关系表 + 分层索引（文档级摘要 / 章节级小结 / 段落级主块 / 原子命题级细粒度）。
- **失败兜底**：无法抽取的关系不强求；至少保留**位置关系**（相邻、同章节）——这是零成本、任何场景都可得的保底关系。
- **注意**：关系的获取成本分三层，应按需投入（见第 8 章权衡 4）。

## 3. 五个可替换旋钮

骨架不变，下面五件事做成可插拔参数，即可覆盖任意文本类型。

| 旋钮 | 含义 | 知识文献取值 | 其他类型取值示例 |
|---|---|---|---|
| **旋钮 1：结构容器** | 树的节点是什么 | 章节->段落->句子 | 代码：模块->类->函数；对话：会话->话题->话轮 |
| **旋钮 2：边界检测器** | 怎么发现主题/逻辑切换 | 嵌入相似度突变 | 代码：语法树节点；对话：话题漂移；表格：表头/schema |
| **旋钮 3：关系类型** | 块之间靠什么相连 | 论点-论据、引用 | 代码：调用/继承；对话：回复/指代；法律：交叉引用 |
| **旋钮 4：上下文模板** | 前置什么让块自包含 | 标题路径+指代消解 | 代码：import+作用域；对话：说话人+话题 |
| **旋钮 5：粒度映射** | 什么任务取什么粒度 | 问答取段落、摘要取章节 | 补全取函数级、续写取相邻多块 |

**关于旋钮 5 的关键补充**：粒度不只是"任务"决定的，还受两个硬约束钳制——

1. **嵌入模型的上限**：多数嵌入模型对超过其最大输入长度（常见 512/1024 token）的文本会截断，超长块的尾部信息在嵌入时丢失。块长上限必须 <= 嵌入模型最大输入。
2. **检索器的分辨率**：检索返回的 top-k 有限，块越大，单块覆盖越广但**噪声也越大、越稀释**。块大小的下限由"答案是否落在同一块"决定，上限由"单块是否开始变杂"决定。

> 旋钮 3（关系类型）是"步骤 6 保关系"的内容来源；旋钮 4（上下文模板）是"步骤 5 补上下文"的模板来源。五个旋钮并非与六步一一对应，而是**从结构、语义、关联三个维度**共同约束六步的行为。

## 4. 内容类型映射表

| 内容类型 | 语义单元 | 结构容器 | 关键关系 | 上下文前置 | 最大难点 |
|---|---|---|---|---|---|
| **代码** | 函数/类 | 语法树节点 | 调用、依赖、作用域 | import + 签名 + 类型 | 必须按语法树切，不能按行/长度 |
| **对话/会议记录** | 话轮 | 会话->话题->话轮 | 回复关系、话题漂移 | 说话人 + 话题 | 话题时间上非线性，指代密集 |
| **法律/合同** | 条款 | 编->章->条->款 | 交叉引用、定义、例外 | 定义前置 + 引用解析 | 一条款常依赖几十处他处定义 |
| **表格（文本）** | 行/单元格 | 表标题->表头->行 | 表头-数据、跨表引用 | 表标题 + 表头 | 裸单元格无意义，必须带表头结构 |
| **叙事/文学** | 场景/事件 | 章->场景->段 | 时间顺序、人物线 | 人物 + 时间锚点 | 顺序即语义，乱切毁叙事 |
| **邮件/论坛线程** | 单条消息 | 线程->消息 | 回复链、引用 | 引用原文 + 发件人 | 引用嵌套，上下文藏在别处 |
| **百科/FAQ/知识库** | 单个条目 | 主题->条目 | 链接、同义 | 条目标题 | 天然碎片化，但需术语对齐 |

## 5. 进阶：语义图与按需装配

静态切块存在天花板：**切得再聪明，块也是死的**。更彻底的做法是把文本转成**图**，在查询时动态组装上下文窗口。

```
文本 -> 解析成原子单元（节点）+ 关系（边）
     -> 存入语义图
     -> 查询时：定位相关节点 -> 沿边扩展邻居 -> 组装"恰好够用"的窗口
```

为什么这是通式：**"什么是一个块"由关系决定，而不是预先固定**。切块只是图上的一次子图采样：

- 代码：节点=函数，边=调用图，查一个函数自动带出依赖；
- 对话：节点=话轮，边=回复/话题，查一个问题带出整条讨论链；
- 知识文献：节点=命题，边=引用，查结论带出支撑证据；
- 法律：节点=条款，边=交叉引用，查一条自动展开引用的定义。

> 这即 GraphRAG 的核心思路。**静态切块是特例，图是通式。** 但注意：图不替代切块——图的**节点本身就是切块的结果**，只是"取哪些块"从静态变成了动态。

## 6. 落地谱系与选型

### 6.1 三层谱系

| 层级 | 做法 | 适合 | 代价 |
|---|---|---|---|
| **兜底** | 固定长度/规则切 | 无结构杂文本 | 最便宜，效果最差 |
| **主流** | 类型感知静态切 + 元数据 | 单一类型、规模不大 | 性价比最高 |
| **彻底** | 语义图 + 动态装配 | 多类型混合、关系复杂、高召回要求 | 构建成本最高 |

### 6.2 降级路径（保证任何输入都能处理）

```
结构解析成功 --> 类型感知切块（主流/彻底）
结构解析失败 --> 规则切（空行/标点边界）+ 重叠
仍无规则可依 --> 固定长度 + 大重叠 + 全文兜底
```

降级是**每份文档单独决定**的，不是全局开关：一批语料里可以同时存在"走了主流流程"和"走了兜底流程"的文档，各自打上处理方式标签。

### 6.3 量化升级判据（何时从主流升级到彻底）

不要凭感觉升级，用可测信号判断：

| 信号 | 测量方式 | 升级阈值（经验值，可调） |
|---|---|---|
| 答案跨块 | 抽 100 个真实问题，统计答案需要 >= 2 块才能拼出的比例 | > 20% |
| 关系查询频繁 | 统计"要求追踪引用/调用/因果链"的查询占比 | > 15% |
| 多类型混合 | 语料中次要类型的文档占比 | > 30% |

任一信号持续超过阈值，才考虑投入"彻底"层级；否则"主流"足够。

## 7. 实施流程

### 7.1 抽象接口

把骨架固化为一个最小接口，不同文本类型实现自己的适配器：

```
interface Decomposer {
  parse(raw): Intermediate;       // 步骤1：还原解析
  structure(ir): Tree;            // 步骤2：建结构树
  unit(tree): Unit[];             // 步骤3：定语义单元
  chunk(units): Chunk[];          // 步骤4：切块
  context(chunk): Chunk;          // 步骤5：补上下文
  relate(chunks): Relation[];     // 步骤6：保关系
}
```

### 7.2 落地顺序

1. **抽取清洗**：解析器 -> 去噪 -> 还原段落；
2. **结构解析**：识别标题层级 -> 建树 -> 识别表格/公式/列表/引用；
3. **语义切块**：沿树切 -> 段内按语义边界细切（嵌入相似度突变点）；
4. **上下文补全**：指代消解 -> 前置路径 -> 补全省略；
5. **元数据标注**：术语、实体、来源、章节、相邻关系、权限；
6. **分层索引**：摘要/章节/段落/原子命题多级入库 + 向量嵌入。

## 8. 关键设计权衡（易被忽略的五个决策点）

这一章回答"切块之上还有哪些隐性决策"，每个都有代价，需要显式权衡。

### 权衡 1：自包含 vs 冗余

补上下文让块自包含，但**引入重复**：几十个块可能都带着同一段标题路径。重复的危害是——嵌入相近的块增多，检索时误召回、浪费 token。

- **折中**：只补"检索必需的"上下文（标题路径、消解后的关键名词），不补"锦上添花"的背景；冗余控制在块长的 15% 以内。
- **或**：标题路径不塞进块内文本，而是放元数据，检索时用"先过滤章节、再语义匹配"两步走。

### 权衡 2：硬边界 vs 重叠（Overlap）

语义切块边界清晰，但"答案恰好跨边界"的查询会漏。处理有两种，**不叠加**：

- **弱语义切法**（固定长度/滑动窗口）：边界是任意的，必须靠**块间重叠 10-20%** 兜底。
- **强语义切法**（按标题/函数/话轮）：边界是语义的，重叠意义不大、只添冗余；改用**相邻块指针 + 检索时扩展邻居**（命中块后自动带上前后块）来补救。

### 权衡 3：什么进正文 vs 什么进元数据

这是最影响实际效果、却最常被拍脑袋的决策。原则是：**参与语义匹配的信息进正文，只用于过滤/排序/权限的信息进元数据。**

| 信息 | 归属 | 理由 |
|---|---|---|
| 标题路径、消解后的名词、术语定义 | **正文** | 帮助嵌入命中语义 |
| 来源、时间、作者、章节编号、权限 | **元数据** | 不影响"意思"，用于事后过滤 |
| 相邻块指针、块 ID | **元数据** | 检索时组装上下文用，不进嵌入 |

### 权衡 4：关系抽取的成本分层

"保关系"不是非黑即白，按成本分三层，按需投入：

| 层级 | 关系 | 获取方式 | 成本 |
|---|---|---|---|
| L0 位置 | 相邻、同章节 | 切块时自然可得 | 零 |
| L1 规则 | 代码调用、法律引用编号、超链接 | 解析器/正则 | 低 |
| L2 语义 | 论点-论据、因果、赞同-反对 | LLM 抽取 | 高，且有幻觉风险 |

主流层级通常只做 L0 + L1；L2 只在升级到"彻底"且确认 ROI 后做。

### 权衡 5：可复现性

切块结果必须**确定、可复现**，否则增量更新和调试都会漂移：

- 切块算法不用随机种子、不做随机采样；
- LLM 抽取部分：缓存结果 + 版本化 prompt + 记录模型版本；
- 块 ID 基于**结构路径**（如 `docA#sec2.3#para4`），而非自增序号——内容不变，ID 不变。

---

## 9. 质量验收与评估闭环

### 9.1 验收清单（定性）

- [ ] **可读性**：随机抽 10 块，脱离全文能否看懂？（自包含）
- [ ] **完整性**：是否存在被拦腰斩断的语义单元？
- [ ] **无跨界**：是否有块跨越了结构层级？
- [ ] **检索命中**：用真实问题抽样，答案是否落在同一块内？
- [ ] **关系保留**：结论与证据、调用与定义等关系是否可追溯？

### 9.2 量化指标（必须可测）

| 指标 | 定义 | 参考目标（可调） |
|---|---|---|
| **检索命中率 Recall@k** | 答案出现在 top-k 检索结果中的比例 | >= 90%（k=5） |
| **端到端正确率** | 问答/摘要任务的最终正确率 | 相对"整篇塞入"基线不降 >= 5% |
| **块长分布** | 块长的中位数与 P95 | P95 <= 嵌入模型上限，中位数落在任务适配区 |
| **自包含通过率** | 抽样块中"脱离全文可懂"的占比 | >= 95% |
| **冗余率** | 上下文补全引入的重复 token 占比 | <= 15% |

### 9.3 评估闭环

验收不是一次性动作，而是持续回路：

```
上线 -> 采集真实查询 -> 统计失败样本（答案跨块/漏召回）
    -> 定位失败块 -> 调整粒度/重叠/上下文策略 -> 复测对比
```

第 6.3 节的"升级判据"就来自这条回路采集的信号——**没有闭环，选型就是拍脑袋**。

---

## 10. 更新与维护

文本不是静态的，索引要有增量更新能力：

- **稳定块 ID**：基于结构路径 + 内容哈希，未变化的块不重嵌入，只重切受影响的结构子树；
- **变化检测**：文档更新时，对比新旧结构树，定位"变了哪几支"；
- **版本化**：块记录来源文档版本号，检索时可按版本过滤；
- **内容哈希去重**：完全相同内容的块只入库一次，指向多份来源。

## 11. 反模式与陷阱

| 反模式 | 危害 | 正确做法 |
|---|---|---|
| 按固定长度硬切 | 语义被斩断、检索错配 | 按语义边界切，长度作为结果 |
| 只留正文、丢结构 | 模型不知上下文、无法定位 | 前置上下文头 + 元数据 |
| 过度追求细粒度 | 块数暴增、召回噪声大 | 分层：检索主粒度 + 细粒度按需 |
| 忽略关系 | 结论与证据断裂，模型易编造 | 显式保留并标注引用关系（至少 L0） |
| 术语不一致 | 同义表述检索漏召回 | 建术语别名表、统一实体 |
| 忽视表格公式 | 关键信息丢失 | 文字化描述 + 结构化保留（Markdown 表格） |
| 盲目补上下文 | 冗余污染嵌入、误召回 | 只补必要上下文，控制冗余率 |
| 切块结果不确定 | 增量更新漂移、难调试 | 确定性算法 + 稳定块 ID + 缓存 |
| 忽视敏感信息 | 切块后 PII/密钥暴露面变大 | 入库前检测，权限进元数据过滤 |

## 12. 已知边界（诚实声明）

以下问题本文档**未完全解决**，落地时需额外投入或接受其不完美：

1. **对话/会议的"话题识别"本身是开放难题**——第 4 章映射表假设它已解决，实际需专门模型或人工标注。
2. **LLM 抽取语义关系（L2）有幻觉风险**——需人工抽检 + 置信度过滤，不能盲信。
3. **"自包含程度"与"嵌入质量"的关系无公认最优解**——需按具体任务实测，本文档只给出经验区间。
4. **扫描件/图片型 PDF 不在本文档范围**——需先 OCR 得到文本层，OCR 质量直接决定拆解上限。
5. **隐私与合规**（如 GDPR、医疗/金融数据）需按行业规范单独设计，本文档只作通用提示。

## 13. 精简、节省上下文的策略

拆解解决"怎么切、取哪些块"；精简解决"同样信息用多少 token 表达、何时用贵的原文、何时用便宜的摘要"。**两者正交、可组合**——拆解定边界，精简定边界内的信息密度。以下按"省 token 力度"从轻到重排列。

### 13.1 去噪（最安全，永远先做）

移除页眉页脚、版权声明、导航、重复模板、空行、乱码。纯文本文件常含 10-30% 的非信息内容。去噪不改语义，只删垃圾，零风险。

### 13.2 去重

内容哈希去重（同第 10 章），相同块只存一份、指向多份来源。

### 13.3 关键信息前置

LLM 对开头注意力更强（"Lost in the Middle"的反面）。把块的要点、结论、定义放在块首，这样即使块被截断，关键信息仍在。

### 13.4 分层摘要（省 token 的主力）

为块/节/文档预生成逐层摘要，形成摘要树：

- 概览/导航：用文档级 + 章节级摘要；
- 检索：用段落级块；
- 命中确认后：才展开原文或原子命题。

同样的答案，摘要树可把 token 消耗降一个数量级（RAPTOR 等思路）。

### 13.5 压缩（最省，但损细节）

把冗长块压成要点：保留关键事实/数字/结论，删修辞、例子、铺垫。

- 适合：事实型问答、概览、分类；
- 不适合：需逐字引用、法律原文、文学赏析、代码精确性；
- 关键：压缩是"可选的额外一层表示"，**不替换原文**——原文始终是 ground truth。

### 13.6 按需取用粒度（多级索引）

摘要级 -> 段落级 -> 原子命题级，按任务取"最小够用"粒度，不一次全塞：

- 概览取摘要；问答取段落；事实核查/引用定位取原子命题。

### 13.7 Token 预算管理（调用侧纪律）

每次调用设预算，按"相关性 × 信息密度"给候选块排序，优先填充高价值块，预算用尽即停，避免"全塞进去"的默认行为。

> 组合原则：**去噪 + 去重**永远该做（零风险）；**分层摘要**用于降成本；**压缩**只对特定任务开；**关键信息前置**是块内写法习惯；**Token 预算**是调用侧纪律。

## 14. 小结

通解 = **六步骨架（解析->建结构->定单元->切块->补上下文->保关系）不变，五个旋钮（结构容器、边界检测器、关系类型、上下文模板、粒度映射）按文本类型替换**。

其上还有四条贯穿始终的纪律：

1. **每步都有失败兜底**——任何输入都不中断，宁可降级也不丢数据；
2. **五个关键权衡显式决策**——自包含/冗余、硬边界/重叠、正文/元数据、关系成本分层、可复现性；
3. **用指标和闭环代替拍脑袋**——量化验收、量化升级判据、持续评估回路；
4. **拆解与精简正交**——拆解定边界，精简（去噪/摘要/压缩/按需取用）定信息密度。

其极限形式是放弃静态切块、把文本转成语义图按需装配——此时"切块"只是图上的一次子图采样。
