1. **S0-A：工作区迁移安全闸门**
   防止迁移目标校验错误或并发迁移导致用户文件被删除、覆盖或工作区配置错乱。
2. **S0-B：文档与资源统一保存屏障**
   统一自动保存、手动保存、切换、关闭、退出、资源重新导入和删除的写入顺序，防止未保存内容丢失或旧请求覆盖新内容。

   统一项目/实体归属与状态校验，协调后台派生任务，补充多文件操作的提交与恢复机制。

## 二、S0-A 已批准方案

### 目标

工作区迁移失败时保持原工作区可用；任何已有目标文件、链接或未知目录都不得被本软件递归删除或覆盖。

### 安全边界

- 当前工作区与目标路径相同：拒绝。
- 目标位于当前工作区内部：拒绝。
- 当前工作区位于目标路径内部：拒绝。
- 目标路径不存在：允许，迁移时只允许通过原子重命名创建目标。
- 目标路径已存在：默认拒绝，包括普通文件、符号链接、junction、空目录和非空目录。
- 不再使用“删除已有目标目录后再重命名”的策略。
- 同一进程内同时只能有一个迁移任务。
- 迁移过程中的临时目录失败后尽力清理；清理失败不得影响原工作区保留。

### 实施内容

1. 使用 `lstat` 区分普通文件、目录和链接；对已存在目标统一拒绝。
2. 对源工作区检查真实路径，拒绝源工作区本身是链接或无法解析真实路径的情况。
3. 对目标父目录解析真实路径，重新执行越界检查。
4. 迁移提交阶段不删除目标；目标在检查后被其他程序创建时，原子 `rename` 失败并返回错误。
5. 增加迁移互斥锁，防止重复点击、并发 IPC 或配置切换造成竞态。
6. 保留 staging 复制和文件数校验；迁移成功后才更新工作目录配置。

### 主要修改文件

- `src/main/services/migration.service.ts`
- 可能的迁移测试/验证脚本
- 本文档

## 补充：S0-B 复核记录（2026-09-04）

### 实施范围

S0-B 已在不修改既有文件格式、业务流程和真实供应商 API 的前提下实施。本批次只处理进程内的写入串行化、编辑器保存握手、标签关闭保护和退出前 flush。未扩展到 S0-C 的跨进程事务或后台任务生命周期。

### 主要改动

1. `src/main/util.ts`
   - 增加 `enqueueSerialized`，使同一文件的 `atomicWrite` 与 `appendJsonl` 串行执行。
   - 保留原有原子写入和 Windows `EPERM` 重试机制。
   - 处理队列清理时的 promise 对应关系，避免并发任务误判为队列已结束。
2. `src/main/services/file.service.ts`
   - 文档 ID 级写入队列覆盖正文、元数据、重命名、删除、恢复和彻底删除的读改写交易。
   - 聊天 ID 级写入队列覆盖消息追加和最后一条助手消息替换。
   - 资源 ID 级写入队列覆盖文本保存、原文重新导入、覆盖导入和删除。
3. `src/renderer/src/components/editor/EditorPane.tsx` 与 `ResourceViewer.tsx`
   - 自动保存、手动保存、退出 flush 共用保存 promise。
   - 保存请求运行中产生新内容时继续处理最新内容，保存失败时保留 dirty 状态。
   - 资源重新导入前等待未完成的保存，保存失败则取消覆盖。
4. `Tabs.tsx`、`App.tsx`、`index.ts` 与 `editorRegistry.ts`
   - 关闭标签时保存失败不再静默关闭，防止重复关闭。
   - 退出时等待所有编辑器完成，以 `{ ok: false }` 拒绝在保存失败或超时时继续清理退出。

### 复核中发现并即时追加的修正
