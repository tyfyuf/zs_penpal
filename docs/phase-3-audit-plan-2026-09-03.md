## 一、审计目标与约束

阶段 3 专门检查 LLM 调用协议、模型兼容、结构化生成、资源摘要/蒸馏、原文检索和向量索引。当前阶段只发现、记录和归类问题，不修改业务代码，不调用真实供应商 API，不消耗用户额度，也不读取或修改 `settings/` 测试数据。

每个小阶段完成后立即将结论追加到审计汇总文档，并进行 UTF-8、乱码和 `git diff --check` 验证。只有在确认存在独立根因时才新增问题编号；如果只是已有问题在另一入口的表现，则归并到已有编号并补充证据。

## 二、安全拆分

### 3A-1：API 协议请求构造审计

范围：

- Chat Completions 请求构造；
- OpenAI Responses 请求构造；
- 流式与非流式分支；
- Base URL、headers、模型名和上下文上限；
- `max_tokens` / `max_output_tokens`；
- tools/tool choice；
- JSON Schema 与结构化输出参数；
- Chat 与 Responses 参数是否误混；
- 不支持参数时是否存在降级或明确失败。

产出：协议请求参数对照表、适配缺口、可能造成 400/空响应/参数拒绝的路径，以及与阶段 2 问题的去重归类。

### 3A-2：流式响应、思考模式与工具调用

范围：Responses 事件解析、Chat chunk 解析、`content`/`reasoning`/`reasoning_content`、思考过程显示/保存/回放、工具调用协议与降级、工具循环终止、完成事件的 requestId/messageId/error。

### 3B-1：通用结构化生成与标题生成

范围：Prompt 与 JSON Schema 一致性、截断与解析失败、重试和 fallback、空输出/半成品、前端状态回报、标题生成失败率与风格一致性、标题生成和重命名竞态。

### 3B-2：资源蒸馏、文档摘要与大摘要

范围：三类资源蒸馏、分块与 checkpoint、未变化分块复用、单块重试、输出截断、摘要自动生成/维护、过期和重建、大摘要动态学习与裁剪、伏笔字段移除情况。

### 3C：原文检索与向量索引

范围：自动原文检索、工具检索、索引不存在/过期/失败、检索失败对对话的影响、项目/工作区/文档/资源隔离、来源标识、上下文预算、功能指引对话是否完全排除检索、记忆卡片与实际结果一致性。

### 3D：兼容矩阵收口

覆盖普通非思考模型、思考模型、支持/不支持 `reasoning_content` 的模型、支持/不支持工具调用的模型、部分 OpenAI 参数模型、Chat/Responses 两种协议、结构化输出、长文本和免费/限速模型。

### 3E：最终问题与测试矩阵

整理阶段 3 去重结果，区分缺陷、潜在缺陷、产品边界和待人工测试项；为每项记录最小复现条件、影响、建议验证方式和后续统一修复顺序。
