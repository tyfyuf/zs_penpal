# VibeWrite 三层记忆架构方案（定稿 v2.1）

> 状态：**定稿，未实施任何代码。** 本文件为单一事实来源，替代 v1。
> 基础：OpenFic / NeuroBook 源码精读 + 六轮决策。所有"自动读取"行为必须**透明展示给用户**（§5.3）。

---

## 1. 核心架构：三层记忆

```
小摘要（注入层，用户控制）
   ↓ 相关性不足 / 预算不足 / 模型自述缺信息
大摘要（降级层，B 自动点菜，系统自动 + 透明展示）
   ↓ 仍不足 → 模型明说缺什么 → 用户确认（是 / 否，请告诉我关于 X）
向量检索（兜底层，C 用户确认触发，透明展示命中）
```

- 三层共用三件套：**源指纹 + 三级新鲜度（FRESH/STALE/NEEDS_REBUILD）+ 增量更新**。
- 交互主线不变：active/pending/disabled 冻结状态机、zh/en 语言驱动、纯文件存储、隐私红线（无新增上传通道）。

---

## 2. 注入采样：内容相关度（放弃章节邻接）

`DocMeta` 无顺序/章节字段，创作者也可能不按章节数组织故事 → **不猜章节号，用内容相关度**：

> 相关度(候选摘要) = 实体重叠（角色/术语/关键设定交集）+ 新鲜度（updatedAt）+ 序号加分（标题含 `第X章/ch01/01-` 可解析时）+ 用户置顶（pinned）

- 实体重叠用**摘要自带字段**（`characters/keyTerms/keySettings`）计算，**零 LLM**——这是蒸馏与注入共用的基础设施。
- 无顺序、无重名实体时退化为"最近活跃 N 条"兜底。
- 默认采样：文档最相关 10 条；对话 = 关联当前文档 + 最近活跃 10 条；资源 = 最近活跃 + story 优先 10 条。
- 项目级对话无锚点 → 只按最近活跃 + 置顶 + 搜索；文档级对话当前文档摘要**始终注入**。

**配套 UI（降决策疲劳）**：注入列表内加**搜索框**（类型徽标/更新时间/一句话预览，激活置顶且持久化）+ **智能推荐 3 条**（实体重叠，零 LLM）。

---

## 3. 大摘要（rollup）

- 触发：写作文档 > 50 个（可配）时，按**内容顺序每 10 个**生成一个总体摘要（借鉴 OpenFic long_term）。
- 位置：**设置页**，按项目分组折叠；每条可预览、可单条重新生成，**无移除按钮**。
- 内容：**跨块状态变化 / 因果链 / 伏笔账本**（强调"什么变了"，非 10 个小摘要的缝合）。
- 新鲜度：底层文档变更 → STALE + 可重新生成（复用源指纹）。

---

## 4. 向量检索兜底

- **嵌原文分块**（保守方案），命中直接注入分块，**无"命中后再决定"步骤**。
- **本地**：fastembed + LanceDB（零 API、可离线、隐私最干净；包大小不计）。
- 分块：按自然边界（段落/标题）切 600–1000 字，重叠 10–15%；每块元数据 `{docId/resourceId, title, charRange, sourceHash}`。
- 检索：cosine，top-k = 5；置信度 < 0.3 丢弃；注入带 `【来源：文档名 · 第X段】` 头。
- 索引：增量建（只嵌新增/变更块）；换 embedding 模型或分块参数 → 全量重建（OpenFic 新鲜度契约）。
- **触发：仅用户确认（C 门）**，不自动。

---

## 5. 升级机制 + 透明展示

### 5.1 路径选择（定稿）
- **A 全工具循环**：不引入（成本/耗时不可预期）。
- **B 两段式记忆菜单**：作为第 2 层自动降级——小摘要不够时模型自动"点"大摘要。
- **C 用户确认**：作为第 3 层向量检索的门——模型说缺 X，用户批准才跑向量。

### 5.2 B 两段式细节
1. **第一遍（决策）**：注入现有小摘要 + 极薄目录（可扩展项 = `{id, 类型, 标题, 一行预览, token 成本}`）。指令：够就 `{needs:[]}`，不够就 `{needs:[id...], reason:"缺什么"}`。`max_tokens≈100`、低温、schema 校验、失败重试一次。
2. **第二遍（作答）**：展开 `needs` 项后正式回答；`reason` 以一行展示给用户。

成本：每轮多 1 次极小调用。省法：无可点大件时跳过菜单直接单次作答。兜底：解析失败重试一次，仍失败 → 不补充、直接作答，绝不卡住用户；`needs` 按 token 预算截到最多 5 条。

### 5.3 透明展示（用户新增硬性要求）
> **读什么、读了谁、为什么读，全程可见可溯。**

每次回答附一张**"本次记忆"小卡**（可折叠，默认展开，可一键隐藏）：
- **注入的小摘要**：条目数 + 来源列表（文档/对话/资源名，点击跳转）；
- **B 补充的大摘要**：rollup 标题 + 来源项目，点击预览；
- **C 向量命中**：分块来源（文档名 · 第 X 段）+ 命中文本片段，点击跳转原文；
- **模型自述**：`reason`（它当时判断缺什么）。

原则：作者对"AI 记错来源"零容忍，透明是信任根基，不是可选优化。

## 6. 蒸馏系统

摘要与蒸馏是同一件事的两端（原文 → 结构化小体量），**共用地基**（分类/提取/schema/指纹/新鲜度），仅"判定"与"提取模板"分叉。

### 6.1 判定"故事"
- story/other 二元做**注入语义主线**；判定升级为"**整篇主类型 + 分节类型**"：先按标题/首段强信号 + 启发式 + LLM 采样定主类型；超长/混合文档先分节逐节打型，主类型 = 占比最高。
- 信号加权：`第X章/楔子/卷/引号密度/人物代词` 强正；`代码/表格/链接/日志格式/邮件头` 强负。
- 保留 `confidence<0.8 需确认` 与 `mismatch 重选`；**分类结果 + 源指纹落盘，文档变更惰性重分类**。

### 6.2 提取（分级）
1. **小文档（≤ 60% 预算）**：单次全量提取（现状保留）。
2. **大文档（> 60% 预算）**：`chunk → 逐块提取实体/要点 → 去重合并 → rollup`（复用向量层分块基础设施；修复此前 100k 截断翻车）。
3. **混合文档**：先分节判型，再按型套模板——story→角色/情节；data→字段/结构；transcript→发言者/结论/待办；reference→术语/条目。
- 重心：**实体/术语/关键句/可检索条目优先**，overview 精炼（≤200 字）；`docType` 从单一 "other" 扩展为细分枚举。

### 6.3 蒸馏要不要向量检索 —— 不要（主体）
- 蒸馏是"单文档降噪提取"，不是"跨文档查找"，向量检索帮不上提取本身。
- 向量仅在两个**跨文档**场景可选用：① 去重/合并（新蒸馏结果与已有结果向量比对，重合则提示合并/跳过）；② 关联（术语打"也见于《X》"链接）。
- 结论：蒸馏 = 分类 + 分级提取 + 去重合并；向量检索 = 三层架构的读取兜底，两者不同阶段、不混用。

## 7. 附件与全文注入去重（归设计）

- **消息级去重**：某条消息已把该文档作附件/附加 → 该消息的 fullText 注入对该文档跳过。
- **状态互斥提示**：fullText 已开启 → 附加按钮显示"已注入全文，无需附加"；用户仍可点"仅本次附加"，此时临时关持久全文注入，避免双份。
- **语义区分**：附件/附加 = 一次性、读**当前**内容；fullText = 持续、实时。

---

## 8. 生成机制（小摘要强化，P3）

- 小摘要：沿用 StorySummary 结构 + 枚举约束（`plot.function`/`foreshadowing.status`）+ 字数上限（总览 ≤200 字、单情节 ≤80 字）+ 负例"缺信息留空、不编造" + 解析后校验 + 失败重试一次。
- 全部摘要：schemaVersion + 源指纹 + 三级新鲜度；DocSummary 去内嵌全文快照换指纹（省约一半存储）。
- 旧格式摘要：读入标"旧版摘要，点击重新生成"，不静默丢弃。

---

## 9. 侧边栏瘦身（独立项，不阻塞主线）

- 归档区/回收站可挪到设置页、按项目管理，保证侧边栏只留"工作材料"。
- 大摘要不进侧边栏（已在设置页）。
- 独立立项，可并入 P1′ 同批 UI 改动。
