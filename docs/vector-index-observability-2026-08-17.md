# 向量检索可观测性与索引管理实施记录（2026-08-17）

## 本轮目标

摘要注入保持不变，补齐原文向量检索的可观测性与人工管理入口：

- 设置页展示每个项目的索引是否存在、嵌入后端、更新时间、总分块数，以及每个文档/资源的索引状态。
- 设置页提供“生成/刷新索引”按钮。
- “本次记忆”卡片区分摘要注入、大摘要和向量检索原文。
- 向量命中项展示文件、分块编号、相似度和原文预览；未触发、已检索但未命中、规划/检索失败均显示状态。

## 当前实现

### 索引状态

`vector-index/<projectId>.json` 新建索引时保存 `sources` 元数据：源 ID、类型、标题、正文 SHA-256 指纹和分块数。新增 `vector:status` IPC，由主进程读取当前项目文档/资源并与索引指纹比较：

- `已索引`：索引存在，源正文和标题与生成时一致；
- `可能过期`：正文或标题变化，或索引格式不兼容；
- `未生成`：没有对应索引分块。

旧索引没有 `sources` 时仍可读取；只要存在对应分块，会显示为已索引，但无法判断正文是否变化，手动刷新后会获得指纹信息。

### 记忆规划与卡片

记忆规划提示已明确要求：当问题询问具体事实、细节、例外、出处、设定或其他可能只存在于原文的信息时，即使摘要有概括，也应生成 `vectorQuery`。

`streamDone.memory.vectorTrace` 记录：

- `skipped`：本次规划没有触发向量检索；
- `hit`：检索命中并将原文片段注入 LLM；
- `empty`：已检索但没有命中；
- `failed`：记忆规划或检索过程失败，但不阻断回答。

向量命中继续作为 system message 注入，同时把片段文本、相似度分数和来源保存到记忆卡片数据中。这样“本次记忆”不是只有摘要，而是本次回答实际使用的摘要、大摘要和原文检索上下文。

## 尚待实机验证

1. 打开设置页，为含有资源区设定集的项目点击“生成/刷新索引”，确认资源文件显示已索引及分块数。
2. 修改资源正文后重新进入设置页，确认该资源显示“可能过期”。
3. 询问资源原文中的具体事实，确认“本次记忆”出现“向量检索”区域、检索词、命中数、来源和原文预览。
4. 分别观察未触发、已检索未命中、模型规划失败三种状态。
5. 在本地神经模型不可用时确认按钮反馈为特征哈希后端，回答仍可继续。
6. 检查低配置机器上状态查询（会读取当前文档/资源正文并计算指纹）的耗时；必要时再增加缓存或保存时防抖刷新。

## 后续可选方向

- 为索引状态增加“只刷新过期文件”或增量构建，避免大型资源每次全量嵌入。
- 将索引构建进度以事件形式显示，而不是只显示按钮 busy 状态。
- 为向量命中卡片增加展开全文/跳转到资源分块的交互。
- 继续根据实际命中日志调整 `vectorQuery` 规划策略；本轮没有强制每条消息都检索，以避免无关问题增加延迟。
